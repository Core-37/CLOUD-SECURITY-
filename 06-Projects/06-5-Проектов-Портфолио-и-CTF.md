## 🛠️ Проект 1: Hardened AWS VPC & EC2 Baseline в Terraform + DevSecOps CI/CD
- **Что ты строишь:** Описание безопасной облачной инфраструктуры в коде (`main.tf`): Public + Private + Isolated подсети, закрытые Security Groups, зашифрованный S3 с Block Public Access и сервер EC2 с включённым **IMDSv2** (`http_tokens = "required"`).
- **Секретная фишка для работодателя:** Добавь файл `.github/workflows/security-scan.yml`, который при каждом `git push` автоматически запускает **Checkov** и **Gitleaks**! Покажи скриншот в `README.md`, как сканер поймал умышленную ошибку и затем прошёл проверку зелёным цветом.
- **Основа уже есть в курсе:** возьми за старт наш [`sample_vulnerable_main.tf`](../02-Labs/sample_vulnerable_main.tf) и исправь его по правилам `lab03_terraform_sec_check.py`.

## 🐍 Проект 2: Python Cloud IAM & S3 Security Auditor (Automation)
- **Что ты строишь:** Утилиту на Python (`boto3` для LocalStack/AWS или анализ JSON), которая проверяет аккаунт на 5 самых опасных ошибок: политики с `"Action": "*"`, опасный `iam:PassRole`, публичные бакеты, отсутствие MFA у пользователей и открытый порт 22 (`0.0.0.0/0`).
- **Секретная фишка:** Генерация аккуратного Markdown/JSON отчёта с разделением по критичности (`CRITICAL / HIGH / MEDIUM`) и подсказками *How to Remediate*.
- **Основа уже есть в курсе:** доработай [`lab01_s3_and_iam_auditor.py`](../02-Labs/lab01_s3_and_iam_auditor.py) под `boto3` и протестируй на **LocalStack**!

## 💥 Проект 3: SSRF ➔ IMDSv1 Exploitation & IMDSv2 Defense Lab + Writeups `flAWS.cloud`
- **Что ты строишь:** Репозиторий с воспроизводимым стендом (на Docker / Python), показывающим цепочку взлома **Capital One** (как через баг SSRF злоумышленник забирает временные ключи с `169.254.169.254` и как IMDSv2 блокирует это со статусом `401 Unauthorized`).

## 🐳 Проект 4: Hardened Container & Kubernetes Security Pipeline (`Trivy` + `Kubescape`)
- **Что ты строишь:** Сравнение «Плохого» и «Безопасного» `Dockerfile` и манифестов Kubernetes (`deployment.yaml`).
- **Что показать в README:**
  1. Уязвимый вариант (`FROM ubuntu:latest`, запуск от `root`, флаг `privileged: true`, смонтированный `docker.sock`).
  2. Отчёт сканера **Trivy** (десятки `CRITICAL` уязвимостей).
  3. Исправленный вариант (`distroless/alpine`, `USER 10001`, `readOnlyRootFilesystem: true`, `allowPrivilegeEscalation: false`, `NetworkPolicy` для изоляции базы данных).
  4. Скриншот отчёта Trivy с **0 Critical CVE**.

## 📡 Проект 5: Cloud SOC Playbook, CIS Audit (Prowler) & KQL Detection Rules
- **Что ты строишь:** Готовый пакет защитника (Blue Team / Cloud SOC):
  1. Плейбук реагирования на инцидент **«Утечка AWS Access Key / Компрометация аккаунта Azure»** (шаги Containment ➔ CloudTrail Investigation ➔ Eradication).
  2. Пример отчёта аудита тестовой среды утилитой **Prowler** по стандарту **CIS Benchmark**.
  3. Набор из 5–10 готовых **KQL-запросов** для **Microsoft Sentinel** (поиск перебора паролей, отключений MFA, создания бэкдор-ролей).
