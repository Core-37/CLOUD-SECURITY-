## 🐧 1. Linux & SSH в Облаке
1. **`chmod 400 key.pem` — зачем и почему без этого не пустит SSH?**
   - Ставит права «читать только владельцу» (`-r--------`). Если к приватному ключу есть доступ у других юзеров ПК, SSH из соображений безопасности отказывается им пользоваться!
2. **`ssh-keygen -t ed25519` — что создаёт?**
   - Создаёт пару ключей: **публичный (`.pub`)** кладём на сервер в `~/.ssh/authorized_keys` (как замок), **приватный** остаётся у нас (как ключ).
3. **Команда `sudo ss -tulnp` — что показывает?**
   - Все открытые сетевые порты и программы, которые сейчас «слушают» сеть на сервере (TCP/UDP, Listening, Numeric ports, Processes).
4. **Почему `0.0.0.0:22` в выводе `ss` опаснее `127.0.0.1:22`?**
   - `127.0.0.1` принимает подключения только с самого сервера (localhost). `0.0.0.0` слушает все сетевые карты — дверь открыта наружу!
5. **`PasswordAuthentication no` в `/etc/ssh/sshd_config` — зачем?**
   - Запрещает вход по паролю по SSH, оставляя вход **только по криптографическим ключам** (защита от брутфорса ботами).
6. **Как посмотреть неудачные попытки взлома SSH на Arch Linux vs Ubuntu?**
   - Arch: `journalctl -u sshd | grep "Failed"` • Ubuntu: `grep "Failed" /var/log/auth.log`.
7. **`find / -perm -4000 -type f 2>/dev/null` — что ищем?**
   - Файлы с битом **SUID** (запускаются с правами владельца/root) для проверки локального повышения привилегий (PrivEsc), а `2>/dev/null` прячет ошибки доступа.

## 🌐 2. Сети, Порты и CIDR Подсети
8. **В чём разница между `10.0.1.0/24` и `203.0.113.5/32`?**
   - `/24` = **весь подъезд** (256 IP-адресов от `.0` до `.255`, обычно одна подсеть Subnet). `/32` = **ровно одна квартира** (1 конкретный IP, ставим для своего IP!).
9. **Что означает `0.0.0.0/0` в правиле Security Group?**
   - **Весь интернет (любой человек на планете Земля).** Для портов `22` (SSH), `3389` (RDP) и баз данных (`5432`, `3306`, `6379`) это критическая дыра!
10. **Какой порт у Kubernetes API, kubelet, PostgreSQL, Redis, SSH, RDP?**
    - `22` = SSH • `3389` = RDP • `5432` = PostgreSQL • `6379` = Redis • `6443` = K8s API • `10250` = Kubelet.
11. **Что такое Private Subnet vs Public Subnet в облаке?**
    - **Public** имеет маршрут к `Internet Gateway (IGW)` (тут стоят ALB и NAT). **Private** не имеет маршрута в IGW и публичных IP — сюда прячут серверы и базы данных!
12. **Как сервер в Private Subnet скачивает обновления, если у него нет Public IP?**
    - Через **NAT Gateway** в Public Subnet: сервер сам стучится наружу за патчами, но с интернета к нему войти нельзя!
13. **Security Group vs Network ACL (NACL) — главное отличие?**
    - **SG** = телохранитель у самого сервера, *Stateful* (помнит ответ) и поддерживает только **Allow**. **NACL** = шлагбаум на подсети, *Stateless* (проверяет и вход, и выход) и умеет явно делать **Deny** плохим IP.
14. **Что такое VPC Endpoint?**
    - «Частный подземный кабель» внутри облака, чтобы серверы в Private Subnet общались с S3 или KMS без выхода в открытый интернет.

## 🔑 3. IAM, Ключи, Политики и Шифрование
15. **Главное правило оценки прав в IAM?**
    - По умолчанию всё **Запрещено (Implicit Deny)** ➔ любой **Explicit Deny** бьёт любой **Allow** ➔ иначе нужен явный **Allow**.
16. **Чем IAM User отличается от IAM Role? (И по каким буквам ключа их узнать?)**
    - **User** = постоянный сотрудник (ключ начинается на **`AKIA...`**). **Role** = временная шляпа с токеном STS (ключ начинается на **`ASIA...`** + нужен `SessionToken`!).
17. **Почему Root-аккаунт облака нельзя использовать для повседневной работы?**
    - У Root безграничные права (вплоть до удаления аккаунта и биллинга). Ставим на него аппаратный/TOTP **MFA**, не создаём Access Keys и убираем в сейф.
18. **Что означает в политике `"Action": "*", "Resource": "*"`?**
    - **Права Бога (AdministratorAccess)** — полный доступ ко всему облаку. Нарушает принцип минимальных привилегий (Least Privilege).
19. **Что такое блок `"Condition"` в JSON-политике IAM?**
    - Дополнительное условие допуска, например: разрешить доступ к бакету **только** при наличии MFA (`aws:MultiFactorAuthPresent: true`) или с корпоративного IP (`aws:SourceIp`).
20. **Что такое STS (`AssumeRole`)?**
    - Служба выдачи короткоживущих временных ключей (`15 мин – 12 ч`), чтобы не хранить вечные пароли на серверах и в коде.
21. **Как работает Envelope Encryption в KMS?**
    - Главный ключ **CMK** навсегда сидит в сейфе KMS (HSM) и шифрует лишь одноразовый **Data Key (DEK)**, а сам файл шифруется быстрым DEK. Без права `kms:Decrypt` файл не прочитать!

## 🪣 4. Облачные Хранилища (S3 / Azure Blob)
22. **Какие 4 настройки защищают S3-бакет от утечки данных?**
    - 1) **Block Public Access** (включён на всём аккаунте); 2) Отключены старые ACL (`BucketOwnerEnforced`); 3) Шифрование **SSE-KMS** + требование HTTPS (`aws:SecureTransport`); 4) **Versioning** от шифровальщиков.
23. **В чём ловушка группы `AuthenticatedUsers` в AWS S3?**
    - Это **НЕ** сотрудники твоей компании! Это **ЛЮБОЙ человек на планете**, зарегистрировавший бесплатный аккаунт AWS (уровень 2 в `flAWS.cloud`).
24. **Как анонимно проверить, не открыт ли публично учебный бакет S3?**
    - Командой `aws s3 ls s3://имя-бакета --no-sign-request`.
25. **Как называется аналог S3 в Azure и GCP?**
    - В Azure — **Azure Blob Storage** (проверяем, чтобы Public Access был `Private`). В GCP — **Google Cloud Storage (GCS)**.

## 💥 5. Атаки на Облака (Red Team & Инциденты)
26. **Что такое `169.254.169.254` в AWS / Azure / GCP?**
    - Внутренний адрес службы метаданных сервера (**IMDS**). Через него приложение узнаёт свой IP, имя и **временные секретные ключи своей IAM-роли**!
27. **Как взломали Capital One (100+ млн записей)?**
    - Хакер нашёл баг **SSRF** на сервере ➔ заставил сервер сделать запрос на `http://169.254.169.254/latest/meta-data/iam/security-credentials/` ➔ украл STS-ключи роли с устаревшего **IMDSv1** ➔ выкачал бакеты S3 из-за широких прав!
28. **Как IMDSv2 блокирует атаку SSRF ➔ IMDS?**
    - Требует сначала отправить запрос методом **`PUT`** за одноразовым токеном, затем передать токен в заголовке `GET`-запроса + блокирует прокси-заголовки (`X-Forwarded-For`) и ограничивает `Hop Limit = 1`.
29. **Назови 3 главные комбинации IAM Privilege Escalation!**
    - 1) `iam:PassRole` + `ec2:RunInstances` (или `lambda:CreateFunction`); 2) `iam:CreatePolicyVersion` (переписать свою политику на `*`); 3) `iam:AttachUserPolicy` (повесить на себя `AdministratorAccess`).
30. **Что такое Subdomain Takeover в облаке?**
    - Старая DNS-запись `CNAME` компании всё ещё указывает на удалённый S3-бакет или Azure App, и злоумышленник регистрирует это свободное имя в своём облаке!
31. **Что делать ПЕРВЫМ при утечке AWS Access Key? (НЕ удалять ключ сразу!)**
    - 1) Нажать **Deactivate** (отключить ключ, сохранив историю); 2) **Revoke active sessions** (сбросить активные токены); 3) Проверить **CloudTrail** по `AccessKeyId` во всех регионах на создание скрытых админов (`CreateUser`, `RunInstances`)!

## 🐳 6. Docker, Kubernetes, Terraform и Cloud SIEM
32. **Почему флаг `--privileged` в Docker смертельно опасен?**
    - Снимает изоляцию устройств: внутри контейнера можно смонтировать физический диск сервера (`/dev/sda1`) и получить `root` на хосте!
33. **Чем опасен проброс `-v /var/run/docker.sock:/var/run/docker.sock`?**
    - Позволяет процессам изнутри контейнера управлять самим демоном Docker на хосте и запустить новый привилегированный контейнер с корнем `/`.
34. **Какие 4 слоя входят в модель 4C безопасности Kubernetes?**
    - **Cloud** (облако/VPC/IAM) ➔ **Cluster** (RBAC/etcd/NetworkPolicy) ➔ **Container** (non-root/Trivy/PSS) ➔ **Code** (SAST/без секретов).
35. **Какой компонент K8s хранит все секреты и пароли кластера?**
    - База **`etcd`** на Control Plane — её обязательно шифровать (Encryption at Rest) и закрывать от доступа с сети!
36. **Почему файл `terraform.tfstate` НЕЛЬЗЯ загружать на публичный GitHub?**
    - Внутри `.tfstate` в открытом виде лежат все IP-адреса, структура сети, а часто — пароли от БД и приватные ключи, созданные Terraform!
37. **Разница между `Gitleaks`, `Checkov`, `Trivy` и `Prowler`?**
    - **Gitleaks** — ищет забытые ключи/пароли в Git. **Checkov** — ищет ошибки в коде Terraform/YAML *до* деплоя. **Trivy** — ищет уязвимости (CVE) в Docker-образах. **Prowler** — проверяет *живой* аккаунт AWS/Azure/GCP по стандарту CIS.
38. **Главные сервисы мониторинга и SIEM в AWS vs Azure?**
    - **Логи API:** `AWS CloudTrail` ↔ `Azure Activity Log`. **Умный детектор:** `Amazon GuardDuty` ↔ `Microsoft Defender for Cloud`. **SIEM:** `AWS Security Hub` ↔ `Microsoft Sentinel (язык KQL)`.
39. **Как работает автоматическая изоляция взломанного сервера (SOAR)?**
    - `GuardDuty` находит угрозу ➔ `EventBridge` ловит событие ➔ запускает `AWS Lambda`, которая за 3 секунды вешает на сервер пустую Security Group «Карантин» и снимает снапшот для расследования.
40. **Что такое Shared Responsibility простыми словами?**
    - Провайдер защищает **само облако** (железо, дата-центр, кабели), а ты защищаешь **всё внутри облака** (свой Linux, открытые порты, IAM, шифрование и S3).
41. **Зачем использовать `jq` в терминале при работе с облаком?**
    - Ответы `aws-cli` и `az-cli` приходят в виде огромных JSON-простыней. Утилита `jq` мгновенно достаёт нужные поля прямо в командной строке (напр., `| jq '.Users[].UserName'`).
42. **Как войти на облачный Linux-сервер без открытия порта `22` в интернет?**
    - Через **AWS Systems Manager (SSM) Session Manager** (роль с политикой `AmazonSSMManagedInstanceCore`) или **Azure Bastion**.
43. **Что такое OIDC в связке GitHub Actions + AWS/Azure?**
    - Способ деплоить код из GitHub в облако **вообще без создания вечных паролей и Access Key** — GitHub получает одноразовый токен ровно на 1 запуск!
44. **Что делать, если случайно запушил AWS-ключ в публичный GitHub-репозиторий?**
    - Считать ключ **скомпрометированным навсегда** (боты крадут его за ~15 секунд!): 1) Немедленно деактивировать/удалить ключ в IAM; 2) Проверить биллинг и CloudTrail на майнеров; 3) Очистить историю Git (`git filter-repo`), т.к. просто `git rm` не удаляет ключ из старых коммитов!
45. **Главный совет CISO Marius Poskus для резюме без опыта в Cloud Security?**
    - *"Proof over Paper"*: 5 реальных проектов на GitHub (Terraform + Checkov + Python аудитор + разборы `flAWS` + Cloud SIEM Playbook) + бесплатные бейджи сильнее стопки купленных бумажек!
